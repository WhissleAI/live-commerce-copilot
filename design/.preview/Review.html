Design review · before we build

Eighteen artboards, read as one product.

What is missing, what is cluttered, and what the design promises that the code cannot do yet. Everything here is scoped against the PRD's one user — a solo seller who is on camera while the show runs.

Cross-cutting

Six things every screen needs and none of them has.

P0Three states, not one

Every surface is drawn full of data. Empty, loading and failed are the states an operator actually meets first — a show with no proposals yet, a gateway that 402s mid-show, a catalog that never finished indexing.

P0Destructive actions need a sentence

Delete removes the session, its Whissle agent and its knowledge base. The confirm has to name all three, and say what survives — the audit chain does not, and that is worth knowing before you click.

P1The six pills are unexplained on first use

Position carries meaning only once someone has learned the row. A one-time legend on the first proposal of a seller's first show, dismissed forever after.

P1Nothing confirms what just happened

A send, a commit, a rollback each change the world and produce no acknowledgement outside the card that scrolled away. One toast rail, bottom-left, carrying the undo for the last committed action.

P1Reload loses the conversation

Chat and proposals are persisted per show but the console does not rehydrate them, so a refresh mid-show shows an empty queue beside a live audit chain. The rows exist; the read does not.

P2Desktop only, for someone holding a phone

The console is h-screen with the chat rail hidden below 1280px. The seller in the PRD is on camera with a phone propped beside them. A glance view is a decision, not a stylesheet — flagged under Open decisions.

Found while reviewing

Six defects the design made visible.

P0Anyone can move the autonomy rung

POST /api/autonomy has no write guard, while send, approve and rollback all do. A guest — or an unauthenticated caller — can switch a show to auto-reply.

P0Promotion counts other people's shows

Readiness reads the last five reports globally, not the ones belonging to this account. A stranger's clean show can promote you, which is exactly the guarantee the ladder is supposed to make.

P1Ingest health is emitted and ignored

The server sends a source event carrying connecting / connected / failing for the eBay watcher, and an error event for an unknown show. The browser subscribes to neither — the same bug already fixed once for audio levels.

P1The stream ignores which show you opened

The console opens its event stream with no show id, so it always follows whichever show the server considers active. Two tabs on two shows cannot work, and the server already supports the parameter.

P1Vision spend is invisible

The meter counts a visual_read door; the client's door list does not include it, so every camera read is metered and then rendered nowhere.

P1A show that failed to report disappears

The shows list is built from reports, and report generation swallows its own failure. A session that ended badly — the one you most want to look at — leaves no row.

Open decisions

Three calls — two of them now made.

OPEN
A phone glance view?

The seller is on camera with their hands full. A phone view showing only the top proposal and a send button is either the most-used surface in the product or a distraction from the desktop console. It is roughly a week either way.

My call: not before the submission. It splits the interaction model while the desktop one is still being proven.

DECIDED
How hard do we push discovery?

The endpoint exists and answers when eBay lets it. Making it reliable means defeating a bot-detection control on a site we do not own.

Settled: best-effort, labelled “best effort” everywhere it appears, with a real empty state that points at the paste field. Followed sellers — one link per seller, polled on their own show page — is the dependable path, and the two are never presented as equivalent.

DECIDED
Does L4 ship at all?

Bounded auto-acting only ever runs against a mock marketplace today. Drawing the rung is honest; enabling it against a mock and calling it autonomy is not.

Settled: visible and locked, everywhere — the ladder menu, the readiness table, automation defaults and the landing page all carry the same reason: no live marketplace adapter. It unlocks when an adapter does, not when the rollback rate says so.
